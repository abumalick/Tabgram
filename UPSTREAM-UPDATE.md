# Updating Tabgram to a new upstream release

Tabgram is a patch stack on branch `tabgram`, based on upstream `DrKLO/Telegram`. Fork-owned code lives in separate files; upstream files carry small hooks, mostly a call into `org.telegram.tabgram.*` by its fully qualified name.

## Layout

| Path | Content |
| --- | --- |
| `tabgram.gradle` | Build identity and string wiring; applied by the last line of the root `build.gradle` |
| `TMessagesProj/src/tabgram/java/org/telegram/tabgram/` | Library Java |
| `TMessagesProj/src/tabgram/res/values/strings.xml` | New library strings |
| `TMessagesProj/src/test/java/org/telegram/tabgram/` | JVM unit tests |
| `TMessagesProj_App/src/tabgram/` | App overlay: resources overriding upstream's by name, manifest that removes the launcher aliases |
| `scripts/tabgram-*` | Footprint, smoke test, wordmark generator |

Strings: the app reads `assets/localization_*.bin`, generated by upstream's `TelegramStringsTask` from a list of `strings.xml` files where the later file wins. `tabgram.gradle` appends the fork string files in `afterEvaluate`. The task's up-to-date check ignores input order, so after changing only the order of the string inputs, rerun the strings task with `--rerun-tasks` (or clean).

Wordmark drawables are generated by `uv run scripts/tabgram-wordmark.py`. Vectors need `fillType="nonZero"`, as upstream's, so AGP rasterises them identically.

## Update steps

```sh
git remote add upstream https://github.com/DrKLO/Telegram.git   # if missing
git config rerere.enabled true
git fetch upstream --tags
git rebase --onto <new-upstream-commit> <old-base> tabgram
```

`<old-base>` is the upstream commit the stack currently sits on (`0aae9598` initially). Resolve hook conflicts: keep upstream's new code and re-apply the one-line hook.

Then:

1. Unit tests: `./gradlew :TMessagesProj:testDebugUnitTest`.
2. Release build: `./gradlew :TMessagesProj_App:assembleAfatRelease -Pandroid.injected.build.abi=arm64-v8a -Pandroid.injected.testOnly=false`. Without `testOnly=false`, injecting `build.abi` makes a test-only APK that will not install normally.
3. Device smoke test: `ADBX=<helper> DEVICE=<name> scripts/tabgram-smoke.sh [apk]`. `ADBX` is an adbx-compatible device helper exposing `connect`, `use`, `unlock`, `ui` and `release`; `DEVICE` is the device name it knows.

Both Gradle runs are memory-hungry; on a shared machine, optionally run them under a memory-limited runner (for example a systemd scope with `MemoryMax`).
4. Manual checklist:
   - Logged out: login screen shows "Log in by QR code".
   - Drag All Chats among the folder tabs; the position survives a force-stop and cold start.
   - Premium hidden: Settings has no Telegram Premium row; Chat Settings has the Hide Premium features switch.
   - A sponsored message renders as a compact "Ad · ..." pill.
   - Launcher icon, name, splash and notification icon are Tabgram's.
   - New Contacts switch off: no contact-joined notification.
   - Limited photo access: no permission prompt at startup.
   - Limited photo access: the attach sheet shows the selected photos; its menu has Select more photos, and a newly selected photo appears without a restart.
   - New Contacts switch off: a chat whose last message is "joined Telegram" is hidden from All and the folders and adds no unread count; it reappears when it gets another message or when the switch is turned on. It is also missing from the forward and share pickers.
   - Notifications from two or more chats are not grouped; tapping each one opens its chat.
   - Tablet: open a chat, rotate, Back closes it.
   - Tablet in portrait: with a chat open, tapping another chat's notification opens that chat.
   - Tablet: open Archived Chats, open a chat, rotate: the chat is on the right, Back closes it.

Installing over a previous build needs the same signing key and a `versionCode` at least the installed one. Tabgram's `versionCode` is upstream's code followed by two digits of `tabgramRevision` (`tabgram.gradle`): 7183901 is the first Tabgram release on upstream 71839. Bump `tabgramRevision` for each release on the same upstream version, and reset it to 1 after an upstream update.

## Publishing a release

Releases are GitHub releases on `abumalick/Tabgram`, which users follow with Obtainium. Check the APK (`apksigner verify --print-certs`, `aapt2 dump badging`), then tag the commit it was built from, push only that tag, and upload the APK as-is:

```sh
git tag -a <tag> <commit> -m "Tabgram <versionName> (versionCode <versionCode>)"
git push origin refs/tags/<tag>
cp <apk> .tmp/apks/tabgram-<versionName>-<versionCode>-arm64-v8a.apk
gh release create <tag> -R abumalick/Tabgram --verify-tag --latest \
  --title "Tabgram <versionName>" --notes "<changes>" .tmp/apks/tabgram-<versionName>-<versionCode>-arm64-v8a.apk
```

Obtainium compares the tag with the installed versionName, so `<tag>` is `v` plus the versionName (`v13.0.3`) for the first GitHub release on an upstream version; an installed copy then counts as up to date. Any later release on the same upstream version has the same versionName, so its tag adds the revision: `v<versionName>-<tabgramRevision>` (`v13.0.3-3`). Obtainium offers it to devices on an earlier build and treats it as current once installed, but a device that adds Tabgram to Obtainium while already running that build sees one spurious update.

The branch is rewritten by fixups and rebases, so a release tag usually ends up on a commit that is no longer on `tabgram`; the tag keeps that commit, which the APK names in `META-INF/version-control-info.textproto`.

Pass `-R` because `gh` can resolve a fork to its parent, and push the tag before `gh release create`, which would otherwise create it at the default branch tip.

## Local secrets (gitignored, never committed)

- `unofficial.properties`: `UNOFFICIAL_APP_ID`, `UNOFFICIAL_APP_HASH`, `UNOFFICIAL_STORE_PASSWORD`, `UNOFFICIAL_KEY_ALIAS`, `UNOFFICIAL_KEY_PASSWORD`.
- `unofficial-signing/tabgram.keystore`: PKCS12, so the key password equals the store password.
- `TMessagesProj_App/src/debug/google-services.json` and `TMessagesProj_App/src/release/google-services.json`; the release build fails if missing.

## Footprint

`scripts/tabgram-footprint.sh [base]` (base defaults to `$TABGRAM_BASE` or `0aae9598`; set it to the new upstream commit after an update) prints two diffstats against `base`:

- (a) everything the stack adds, including fork-owned files.
- (b) upstream files only, with the paths in the layout table excluded, followed by the per-file `--stat`. This is the real maintenance burden: the lines that can conflict on the next rebase.
